The big picture

The scope is built around two chips. An FPGA handles everything that has to happen at sample speed: it takes the ADC data, watches for the trigger, fills the memory and runs the generator. An RK3399 processor, six cores and about 4 GB of memory, the same class of chip as in a tablet, runs Linux with the screen, the keys, the network and the mathematics.

The two meet over PCIe. The processor sets the FPGA up through registers, tells it to record, and later reads the finished record. It never sees samples as they arrive.

One analog channel

The front end (one RT1642 per channel) makes any input fit the ADC: it selects the coupling and an input path, sets the gain for the V/div, adds the offset with its own DAC, and limits the bandwidth. It is set over a slow serial bus, so changing V/div takes real time.

The ADC turns the four front ends into 12-bit numbers and sends them to the FPGA on 28 serial lanes. The timing of each lane is measured at every start, because at these speeds every path differs a little.

Why the sample rate depends on the channels

Acquisition: record, then play

The memory works like a tape loop. While armed, samples run in and the oldest fall out, so the part before the trigger is always there. When the trigger fires, the FPGA keeps recording for the post-trigger part and stops. Only then can the processor have the record played to it.

The read path sits between the memory and PCIe. For a live picture it thins out a long record by a factor or stretches a short one by interpolation, so that the transfer stays small. For a full record it is set to pass everything through unchanged. Its settings have to match the read exactly: the FPGA sends a fixed number of points per frame, and a frame that cannot fill it never ends.

In roll and scan mode this changes: at slow time bases the FPGA streams chunks continuously, and the processor builds the moving picture from them.

Trigger

The trigger unit decides when a record is complete. It is built from simple parts that combine into all the trigger types:

PartWhat it does
ComparatorsTwo per analog channel, level A and level B, which is how window and slope triggers get two levels. LA lines use the pod comparators instead. The EXT input, where a model has one, has its own.
Events A and BEach picks comparators, an edge and a pattern over all channels and LA lines (high, low, don't care, combined by AND, OR, NOR).
Time conditionsGreater than, less than, inside, outside, timeout. Time ticks are 1.6 ns and 6.4 ns.
Holdoff and autoHoldoff blocks the next trigger for a time. Auto fires by itself when nothing else does, so the screen keeps moving.

Protocol triggers go a step further in software: the hardware fires on a line, and OOS looks for the wanted field in the decoded record.

Logic analyser

The optional PLA2216 probe adds 16 digital lines. A comparator turns each line into 0 or 1 against the threshold of its pod, and the FPGA packs them into one 16-bit word per sample.

The LA shares the memory with the analog channels, which is why switching it on costs depth. With a channel shown, the analog rate is halved as well.

Generator

The generator of the S models is a direct digital synthesiser in the FPGA. A phase counter steps through a table at a fixed clock; the size of the step sets the frequency. Software fills the table with the wanted shape, so the hardware does not know sine from square.

OOS limits the output to: sine, noise and DC up to 60 MHz, square 15 MHz, pulse 2 MHz, ramp 150 kHz, arbitrary 10 MHz. The output is switched on in a fixed order: relays safe, supply on, relay code, then the FPGA.

Start-up

After a power cut the FPGA, the ADC and the front ends know nothing. OOS brings all of them up by itself; the stock system does not have to run first. Calibration values come from the factory files on the card, which OOS only reads, or from its own self-calibration.

All of this is known from the software side: the device tree, the registers and how the hardware answers. The part numbers of the ADC and the front ends come from there too and have not yet been read off the chips. The inside of the front ends and of the generator output stage is drawn only as far as the software can see it.
