1About This Manual

This manual describes how to control OOS Plus remotely with SCPI (Standard Commands for Programmable Instruments). It applies to OOS Plus running on a supported oscilloscope (DHO800/DHO900-class hardware) and to the OOS desktop application for Windows. Both use the same command interpreter.

OOS Plus implements a subset of the Rigol DHO800/DHO900 SCPI command set, together with OOS extensions for stored references, simulation and analysis. A command that is not described in this manual is not supported, even when the Rigol programming guide lists it. *IDN? identifies the instrument as OOS, not as Rigol.

Conventions

NotationMeaning
:TRIGger:EDGE:SOURceUpper-case letters form the short form (:TRIG:EDGE:SOUR). Either the complete long form or the short form is accepted, in any letter case.
<n>A numeric suffix, for example the channel number in :CHANnel<n>.
[ ]An optional keyword or parameter. :TIMebase[:MAIN]:SCALe may be sent as :TIM:SCAL.
{A|B|C}Exactly one of the listed values.
<source>A waveform name: CHAN1…CHAN4 (inputs present on the model) or R1…R10 (references; REF1…REF10 are accepted too).
OOSMarks a command that is an OOS extension and has no equivalent in the Rigol DHO command set.

Each command entry gives the syntax, a description, the parameters with their type and range, remarks, the format of the reply and an example. Values are always in base SI units: volts, seconds, hertz.

2Programming Overview

2.1Remote Interfaces

All interfaces feed the same SCPI interpreter. Commands from several connections are executed in the order they arrive.

InterfaceDefault portNotes
Raw TCP socket5555Recommended for scripts. One command per line, terminated by line feed (\n). Every reply ends with \n.
HiSLIP4880For VISA libraries that use ::INSTR resources. Basic sessions; locking and overlapped operation are not implemented.
VXI-11111 (portmapper)On the scope only, partial implementation. A read issued while a reply is still pending returns a timeout immediately; prefer the socket or HiSLIP.
HTTP POST /mcpWeb port (8080)JSON-RPC tool scpi for AI agents (Model Context Protocol). Not a VISA interface. It cannot wait for *OPC?.

The interfaces have no authentication. Operate the instrument on a trusted bench network only.

Windows desktop app. By default the desktop application listens on this PC only (127.0.0.1). Start it with --lan to accept connections from other computers. The ports can be changed with --scpi-port, --hislip-port and --web-port.

2.2Connecting

VISA resource strings:

TCPIP0::<address>::5555::SOCKET           raw socket
TCPIP0::<address>::hislip0::INSTR         HiSLIP on port 4880
TCPIP0::<address>::hislip0,14880::INSTR   HiSLIP on another port

With a raw socket, set the VISA read and write termination to line feed. For example with PyVISA:

import pyvisa
rm = pyvisa.ResourceManager()
scope = rm.open_resource('TCPIP0::192.168.1.50::5555::SOCKET',
                         read_termination='\n', write_termination='\n', timeout=10000)
print(scope.query('*IDN?'))

No VISA library is needed for the socket: any language that can open a TCP connection can send commands. Chapter 4 shows a complete client in standard-library Python.

2.3Command Syntax

A command consists of a header, optionally followed by a space and one or more parameters separated by commas. A query is a header ending in ?.

:CHANnel1:SCALe 0.5          command with one parameter
:CHAN1:SCAL?                 query
:MEASure:ITEM? VPP,CHAN1     query with parameters
  • Keywords are case-insensitive. Use either the complete long form or the short form. Intermediate abbreviations (:TRIGG) are not accepted.
  • Several commands may be sent on one line separated by ;. Each must have its complete header starting with :; relative headers after a semicolon are not supported. Send one query per line when its reply itself contains semicolons.
  • Termination: every program message ends with line feed. Carriage return also ends a message, so CR LF works as well.
  • Setters do not reply. Their errors are placed in the error queue (section 2.6). A query always replies, even when it fails, so that a client never waits forever on a wrong query.

Numeric replies. Real values are returned in scientific notation with seven significant digits, for example 5.000000E-01 or -1.500000E-06 (C format %.6E). Integer settings and counts are returned as plain integers. A few replies use other formats; the command entries say so.

Invalid value. Numeric results that do not exist (no edge found, no signal, analysis still being calculated) are returned as 9.9E37. It is never a real measurement. Treat it as "no reading" and query again later if the result may still be pending.

2.5Synchronization

*OPC? waits until the finite operation in progress has completed, then returns 1. The operations it waits for are:

  • an armed single acquisition (:SINGle) until it has captured,
  • Autoset (:AUToscale),
  • a simulation run (:SIM:PLAY ON).

It does not wait for continuous acquisition or for background analysis (measurements on long records, Math, protocol decoding, Eye). Poll those results instead: they return 9.9E37 or BUSY while pending. A single acquisition with no trigger event can wait indefinitely, so set the client timeout accordingly, or poll :TRIGger:STATus? and use :TFORce.

A waiting *OPC? on the raw socket or HiSLIP does not block the instrument or other clients. If the operation is cancelled or re-armed while waiting, the query is interrupted with error -410 and returns no 1. The HTTP/MCP adapter cannot wait and reports error -221.

2.6Error Queue and Status

Errors are queued and read with :SYSTem:ERRor?, oldest first. Each read removes one entry; 0,"No error" means the queue is empty. The queue holds 20 entries; when it overflows the last entry is replaced by -350. Read the queue after each block of configuration commands.

The standard event status register (*ESR?) implements these bits: 0 operation complete, 2 query error, 3 device-dependent error, 4 execution error, 5 command error. Reading it clears it. The service request (SRQ) and status-byte subsystems are not implemented. Appendix E lists the error codes.

Some setters of the channel, timebase, trigger and acquisition subsystems report an invalid parameter value as -113 (undefined header) rather than -224. Treat any non-zero code as a failure of the preceding command.

2.7Binary Data Blocks

Waveform data, screenshots and logic-analyzer data are returned as IEEE 488.2 definite-length blocks:

#<N><length: N decimal digits><payload: length bytes>\n

Example: #9000001200 followed by 1200 bytes and a line feed. Read the length announced in the header and then exactly that many bytes. Never split a binary reply at line feeds; payload bytes can have the value 10.

2.8Waveform Data

:WAVeform:PREamble? returns ten comma-separated values that describe the data returned by :WAVeform:DATA?:

format,type,points,count,xincrement,xorigin,xreference,yincrement,yorigin,yreference
FieldMeaning
format0 BYTE, 1 WORD, 2 ASCii
type0 NORMal, 1 MAXimum, 2 RAW
pointsNumber of points in the transferred page
countAlways 1
xincrementTime between points, s
xoriginTime of the first point of the page, s
xreferenceIndex of the point at xorigin
yincrementVolts per code step
yorigin, yreferenceCode offsets

Integer data converts to time and voltage as:

time[k]  = (k - xreference) * xincrement + xorigin
volts[k] = (code[k] - yorigin - yreference) * yincrement
  • BYTE: one unsigned byte per point.
  • WORD: unsigned 16-bit integers, little-endian (least significant byte first). Scripts written for big-endian data must be changed.
  • ASCii: comma-separated voltages in scientific notation, inside a block. No conversion is needed.

For long records, transfer pages with :WAVeform:STARt and :WAVeform:STOP (one-based, inclusive). A page whose reply would exceed 64 MiB is refused with error -223. Stop the acquisition before reading when the preamble and the data must come from the same capture.

2.9References and Simulation

OOS Plus can load waveform files into ten reference slots, R1 to R10. A reference keeps its native sample rate and timing. It can be read, measured, triggered on (software search through the stored record), decoded and used in Math like a channel, but it is stored data, not an input: it does not acquire new samples. Read a reference's sample rate from its preamble, not from :ACQuire:SRATe?.

The simulator (:SIM subsystem) generates test signals into a reference slot, for use without hardware.

2.10Differences from the Rigol DHO Command Set

  • *IDN? returns OOS,<model>,<serial>,oos-ui <version>.
  • WORD waveform data is little-endian.
  • :WAVeform:MODE RAW is allowed while running. Stop first when preamble and data must match.
  • References can be trigger, measurement, Math and decoder sources.
  • Relative headers after ; are not supported.
  • Only the trigger, bus and status subtrees listed in this manual exist. Check the error queue after configuration.
  • Rigol setup files and the full status/SRQ system are not supported. Settings without a dedicated command are reachable through :SYSTem:SET and :SYSTem:GET? (section 3, System).

4Programming Examples

The examples use Python 3 and its standard library only. They were run against the OOS desktop application.

4.1A Minimal Client

Save this as oos.py. The later examples import it.

import socket

class Scope:
    def __init__(self, host='127.0.0.1', port=5555, timeout=10):
        self.s = socket.create_connection((host, port), timeout=timeout)

    def write(self, cmd):
        self.s.sendall((cmd + '\n').encode('ascii'))

    def _exact(self, n):
        buf = bytearray()
        while len(buf) < n:
            part = self.s.recv(min(65536, n - len(buf)))
            if not part:
                raise EOFError('instrument disconnected')
            buf += part
        return bytes(buf)

    def query(self, cmd):
        self.write(cmd)
        line = bytearray()
        while (ch := self._exact(1)) != b'\n':
            line += ch
        return line.decode('ascii').strip()

    def query_block(self, cmd):
        """IEEE 488.2 definite-length block."""
        self.write(cmd)
        assert self._exact(1) == b'#', 'not a block reply'
        n = int(self._exact(1))
        payload = self._exact(int(self._exact(n)))
        self._exact(1)                       # trailing line feed
        return payload

    def errors(self):
        """Drains the error queue; an empty list means no error."""
        out = []
        while not (e := self.query(':SYST:ERR?')).startswith('0,'):
            out.append(e)
        return out

    def close(self):
        self.s.close()

4.2Set Up, Capture and Measure

from oos import Scope

scope = Scope('127.0.0.1')
print(scope.query('*IDN?'))
scope.write('*CLS')
for cmd in (':CHAN1:DISP ON', ':CHAN1:SCAL 0.5', ':TIM:SCAL 1e-6', ':MEAS:GAT NONE',
            ':TRIG:MODE EDGE', ':TRIG:EDGE:SOUR CHAN1', ':TRIG:SWE NORM', ':RUN'):
    scope.write(cmd)
assert not scope.errors(), 'setup failed'

# trigger halfway between the signal's extremes
vmax = float(scope.query(':MEAS:ITEM? VMAX,CHAN1'))
vmin = float(scope.query(':MEAS:ITEM? VMIN,CHAN1'))
assert vmax < 1e37 and vmin < 1e37, 'no signal on CHAN1'
scope.write(f':TRIG:EDGE:LEV {(vmax + vmin) / 2:.4e}')

scope.s.settimeout(30)                 # *OPC? waits until the single capture is done
scope.write(':SING')
scope.query('*OPC?')
print('Vpp ', scope.query(':MEAS:ITEM? VPP,CHAN1'))
print('Freq', scope.query(':MEAS:ITEM? FREQUENCY,CHAN1'))
print('errors:', scope.errors())
scope.close()

4.3Waiting for a Trigger with a Time Limit

import time
scope.write(':SING')
deadline = time.time() + 5
while scope.query(':TRIG:STAT?') != 'STOP':
    if time.time() > deadline:
        scope.write(':TFOR')           # no trigger event: capture anyway
    time.sleep(0.05)

4.4Reading a Waveform

import struct
from oos import Scope

scope = Scope()
scope.write(':STOP')                   # preamble and data from the same capture
scope.write(':WAV:SOUR CHAN1')
scope.write(':WAV:MODE RAW')           # whole acquisition memory
scope.write(':WAV:FORM WORD')
fmt, typ, points, count, xinc, xorg, xref, yinc, yorg, yref = \
    [float(x) for x in scope.query(':WAV:PRE?').split(',')]
data = scope.query_block(':WAV:DATA?')
codes = struct.unpack(f'<{int(points)}H', data)     # little-endian unsigned 16-bit
volts = [(c - yorg - yref) * yinc for c in codes]
times = [(k - xref) * xinc + xorg for k in range(int(points))]
print(int(points), 'points,', xinc, 's/point')

For records of many millions of points, read pages of, for example, 1,000,000 points with :WAV:STAR and :WAV:STOP.

4.5Saving a Screenshot

png = scope.query_block(':DISP:DATA? PNG')    # without a parameter: 24-bit BMP
open('screen.png', 'wb').write(png)

4.6DDR Write Timing on Stored Captures

DQS captured into R1 and DQ into R2 (loaded from files). Setup and hold are measured for every strobe edge of the whole record, latching on both strobe edges, and the eye diagram is folded on the strobe.

scope.write(':MEAS:GAT NONE')                      # whole record
print('setup', scope.query(':MEAS:ITEM? DSETUP,R1,R2'))   # A = strobe, B = data
print('hold ', scope.query(':MEAS:ITEM? DHOLD,R1,R2'))
# count edges that break 150 ps setup / 150 ps hold
scope.write(':MEAS:TSET 150e-12')
scope.write(':MEAS:THOL 150e-12')
print('violations', scope.query(':MEAS:ITEM? DSETHOLD,R1,R2'))
# eye of R2 folded on the R1 strobe, whole record
scope.write(':SYST:SET eye = R2 0 1')
scope.write(':SYST:SET eye_more = 0.000000000001 1000 1000000 0 - 0 R1 1')
scope.write(':VIEW EYE')
print('eye width', scope.query(':EYE:ITEM? WIDTH'))

A whole-record eye of a long reference is calculated in the background. Until it is finished, :EYE:ITEM? returns the previous result; check that :EYE:ITEM? EDGES and UI belong to the new source before using the figures.
