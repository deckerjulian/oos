## B3: causes and fixes

| finding | cause | fix | evidence |
|---|---|---|---|
| every recording ends at 10 segments for any N | `seg::Status::complete` took any bit of 0x4034 & 0x2320 as "the FSM stopped". The unit sets one of them (bit 5 in the model) after the first frames. The first 10 ms poll then saw 10 frames (1 kHz) and ended the recording | complete only when the count reaches N. The stock record state (0xb) does the same: `RequestNormTrace` forces "not ready", stores `0x4010 - 0x4014 + 1` as progress and stops nothing; the 0x2320 test is only in `getSingleStatus`, not in the record path | code: stock decompilation; cause: the 10 = 10 ms x 1 kHz match. Not yet confirmed on the unit |
| intervals 3.2 x too short | `LATCH_TICK_FS` = 250 ps from the stock API constant | 800,000 fs (0.8 ns) | measured: 1,250,000 ticks per 1.000 ms |
| header k = latch k - 1 | the header stamp lags one frame | `Timeline` uses the latch only; header logged for comparison; `HEADER_TICK_FS` = latch tick | measured |

The record end log now prints 0x4034 (`segments: k of N recorded, 0x4034 0x...`), so the re-test shows which bit is
set.

## B1: causes and fixes

| finding | cause (evidence) | fix |
|---|---|---|
| frames all zero at 625 MSa/s and 1.25 GSa/s, right at 62.5 MSa/s | not found in the register sequence: OOS writes what the stock `ConfigAcquire` writes (0x1004 bit 3 and bit 2 = rate < max / 8, 0x10b0, 0x1148, 0x404c, 0x10e0, 0x1110). The failing and working rates split exactly where the decimation changes path: above 62.5 MSa/s 0x10d0 = 0x8000 \| N, at and below 0x10d0 = 0, 0x10d8 = 62.5 M / rate. 0x1004 bit 2 splits at max / 8 (156 MSa/s at 1 ch); the unit test did not cover 125-312 MSa/s, so the two candidates are not separated | hardware averaging only on the second divider (`spu::slow_path`, 62.5 MSa/s and below); faster rates use the software average. `avg.hw_fast = on` in system.conf lifts the limit for the re-test |
| noise levels off near 0.5 mV (N = 16: 0.53, N = 256: 0.46; raw 1.1) | OOS played only the newest frame of a batch (spec 01 option A). The stock driver plays every recorded frame of a batch in average mode too (`RequestNormTrace`, `SetRun` type 4 with the full count). | 0x10b0 reads N - 1 | it is the written register (netlist: read-back of 0x10b0) | none, diagnostic only |

The 0x10b4 pulse stays as it was: only on a configuration, CLEAR, RUN after STOP, SINGLE and after a complete hold
average (`OOS_HWAVG=hold`). It is not pulsed per frame.

## Unit re-test

Build from `fix/b1-b3`. Signal: probe compensation 1 kHz square on CH1, edge trigger 0.15 V rising, as in the lab log.
Log: `/tmp/oos-ui.log`.

### B3

1. Acquire > Segments, HW segments on, Normal trigger, 100 ns/div. N = 10, 100, 1000 (`:ACQ:SEGM <n>;:ACQ:SEGM:HARD ON`).
   Expect: `segments: N of N recorded` after about N ms; the 0x4034 value in that line noted.
2. N = 1000 with the source at 100 Hz: the recording takes 10 s; STOP after about 3 s. Expect `k of 1000` with k near
   300, and k segments in the history.
3. Times (Segments list or `:ACQ:SEGM:TIMes?`): steps of 1.000 ms at 1 kHz (spread below 1 us), segment 0 at 0.
4. Log lines `segment k latch .. header ..` for k = 1..7: header(k) = latch(k - 1).
5. Interval: Seg. interval 5 ms, 1 kHz source, N = 20: steps of 5 or 6 ms (the next trigger after the interval).

### B1

Noise as in the lab log: 10 us/div, flat top, point-to-point difference / sqrt 2, three records each.

1. 62.5 MSa/s (10 us/div, depth 10k), HW average on. N = 2, 4, 16, 256. Expect roughly 1.1 mV / sqrt(N) down to the
   floor the software average reaches (SW 16: 0.31-0.41 mV). Note the log line `average Running batch k of c
   triggers ... words ...`: c is now the frames played per batch.
2. Settling: N = 16, step the input (probe off the comp terminal, then on). Count batches until the level settles:
   about 16 triggers for a block or running mean, more for an exponential one.
3. Fast rates with the old result expected (software average): 1 us/div (1.25 GSa/s): the top bar does not say "HW".
4. Fast rates in hardware: `avg.hw_fast = on` in /oos/system.conf, restart oos-ui. Same as step 1 at 1 us/div 1k
   (62.5 MSa/s, must still work), 1 us/div Auto (1.25 GSa/s), 10 us/div Auto (625 MSa/s), and at 125, 156 and 312 MSa/s
   (depths chosen for those rates). Record per rate: words zero or not. Zero only above 62.5 MSa/s: the divider path;
   zero only above 156 MSa/s: 0x1004 bit 2. Now that every frame is played, the fast rates may also work: then
   `avg_rate_ok` goes.
5. Remove `avg.hw_fast` afterwards.
